# Class Wiki

Karpathy-style LLM wiki for Ethan's UC Davis classes: lecture transcripts in, an interlinked, fact-checked markdown wiki out, plus NotebookLM-style study outputs. $0: runs on the local `claude` CLI, Docker, ffmpeg, npx. No accounts, no API keys. Local only, nothing deployed.

**Site:** http://localhost:4323 (`serve.py`, stdlib, 127.0.0.1 only). LaunchAgent `com.ethanyap.class-wiki` keeps it running; restart: `launchctl kickstart -k gui/$(id -u)/com.ethanyap.class-wiki`. Log: `serve.log`.
**Phone / other devices:** https://<your-mac>.<tailnet>.ts.net:4323 (Tailscale Serve, tailnet only, NOT Funnel; Mac must be awake). Set once: `tailscale serve --bg --https=4323 http://127.0.0.1:4323`; off: `tailscale serve --https=4323 off`. The Host guard allows this Mac's own tailnet name (`tailnet_name()` asks `tailscale status --json` at start; the CLI is `/usr/local/bin`, not in launchd PATH).

## Classes
`classes.json` is the list (`[{slug, name}]`). Add classes with "New class" on the site. First class: MAT 19A = `mat-19a`.

## Layout
- `raw/<class>/` immutable transcripts · `wiki/<class>/*.md` articles · `wiki/index.md`, `wiki/log.md` (upstream rules)
- `studio/<class>/<kind>/` generated outputs; `studio/<class>/index.html` lists them
- `inbox/<class>/` uploads land here (`inbox/done/<class>/` after ingest, `inbox/<class>/failed/` if a file could not be converted or ingested, `.ingest.log` = every run)
- `ingest.sh <class>` convert (`prepare_inbox.py`) → batch ingest → lint (no auto-quiz: it made one per file, all repeats)
- `prepare_inbox.py <class>`: .pdf → pdftotext (scan → Claude reads it), photos incl. iPhone HEIC → sips → Claude transcribes, `.url` → watch skill (frames + captions) → Claude writes on-screen notes + verbatim transcript. A public Google Doc link (`/api/link`, `*-gdoc.url`) → `fetch_gdoc` downloads `export?format=pdf` (URL rebuilt from the doc ID only; no login) → the normal PDF path. A private doc gets the sign-in page → failed, with "Share → Anyone with the link". PDF originals → `raw/<class>/files/` (unique names); photos are deleted once their notes exist (Claude titles each one). Site: Sources = one row per `raw/<class>/*.md`, titled by its `# ` heading, full-text search via `/api/search`
- `study.sh <class> <kind> [topic]` one headless `/study` (Sonnet; report/exam Opus). Site "Study tools" buttons → `/api/study` → same one-at-a-time queue as ingests. Stop → `/api/cancel` (study jobs only): drops a waiting job, or kills the running job's whole process group (claude, docker). Quiz/card answers → `/api/score` → `studio/<class>/scores.json` (weak spots on the class page; `/study exam`, quiz and cards read it)
- "Ask Claude" chat on each class page → `/api/chat` → one `claude -p --safe-mode --tools ""` per question (Sonnet), prompt = whole `wiki/<class>/` + last 20 messages. Not queued (runs beside ingests). Chat history lives only in the open page ("Quiz me" switch: Claude asks, grades, and its `SCORE:` lines go to scores.json)
- Learning features (PSC 001 "desirable difficulties"): wiki pages get Recall from memory + Write a summary → `/api/grade` (one `claude -p`, `VERDICT: right|wrong`), a pre-test on never-scored pages from existing quiz JSON (`/api/questions`, no Claude call), a re-read warning (localStorage). Quiz short answers are typed + Claude-graded, a miss repeats once; cards need a typed guess before the flip. Source links take `?sec=<heading>` → the viewer scrolls there. Weak spot under 50% after 10+ answers → "ask for help" note. Quiz questions put each concept in a NEW situation (never the lecture's own numbers); the last 2 are "Challenge" (typed, with a Hint). MCQ JSON has `why` (one line per choice): a wrong pick shows why that choice is wrong. Old quizzes without it show only `explain`. A wrong quiz/card answer (with `q`) → `studio/<class>/missed.json` → "Missed questions" on the class page, until a later right answer (a same-quiz retry does not clear it). Section links flash the whole section yellow for 3 s.
- Syllabus: class names must match the planner's course labels (letters and digits only: "ECH 1Y", not "ECH 001"). `serve.py` copies `/api/deadlines` (via `exam_dates.fetch`) to `.planner-cache.json` (gitignored) every 30 min. `/api/class` gives `coming` + `focus`; `/api/classes` gives `next`. Buttons "Quiz/Flashcards: next exam" send `--exam next` to study.sh. Chat prompt has the syllabus.
- Daily review: `serve.py` `daily_loop` (from 5 am, checked every 10 min) queues `study.sh <class> daily [--exam-in N]` once a day per class with wiki pages → `studio/<class>/daily/<date>.html`. `daily_pick.py` picks pages: due by `review.json` (Leitner boxes per wiki page, written on every `/api/score`: right = next box, once a day; wrong = box 0, back tomorrow), up to 3 new pages (more when an exam is near), missed questions; `avoid` = every past question on those pages. `concepts` = one slot per question: a concept is one `## ` heading (not Overview/See Also/Past questions/Sources, unless Overview is all there is; not "Example..."/"...example" headings, which illustrate a concept on the same page; named studies DO count), counted by `(source, section)` across every studio JSON; due page = its least-asked heading, new page = two, missed keeps its own. Ranking is by count, never by page, so a page's concepts rotate. `--check` fails a quiz over 15 min or with two questions on one concept. Nothing due = no file. Ingest makes no quizzes (it made one per file: all repeats).
- Past questions (any class): upload test/quiz questions (e.g. Canvas screenshots in a Google Doc → PDF). `prepare_inbox.py`: a PDF with pictures (`pdfimages -list`, image >= 100x50) keeps its pdftotext text and Claude adds a `## Text in pictures` section (typed text stays exact). `ingest.sh` puts each question on its concept's page under `## Past questions` (never an answer choice as a fact unless marked correct; graded work: full points = correct, lost points = 'Ethan got this wrong', matched to a score table on another page; one page per concept, never one page per test). Claude transcriptions write [removed] for student IDs, emails, phones (a real diagnostic test had his ID). `daily_pick.tested()` counts those bullets: tested new pages come first in the daily review, `tested` in its JSON, `/api/class` pages have `tested`. Site: "On a test" pill; Quiz tab "Past test concepts" button. SKILL.md: tested pages get more questions, in the teacher's style.
- Notes sheet (PSC 001 allows one double-sided letter sheet in exams): Study tab "Notes sheet" / "Notes sheet: next exam" → `/study sheet` (Opus) → JSON → `build_sheet.py` → `studio/<class>/sheets/*.html`, 2 printable sides, name line on side 1. A DRAFT he copies by hand (writing it = studying). Ranked weak → missed → tested → core; > 800 words exits 1 so Claude cuts. Check fit: Chrome `--print-to-pdf` must give 2 pages (`.side` is `overflow:hidden`, so too much text is clipped, not spilled).
- Not tested: `classes.json` `"not_tested": [page file names]` per class (PSC 001: course intro, study strategies, finding your purpose, growing your brain, dealing with stress, unit-1-test-scope). Pages stay in the wiki, chat and Sources; `daily_pick.not_tested()` is the one reader. Skipped by daily review, weak spots, pre-test, Quiz me, and (via SKILL.md) quiz/cards/sheet/exam.
- Test scope: `wiki/<class>/*-test-scope.md` = the instructor's study guide (PSC 001: `unit-1-test-scope.md`, raw `raw/psc-001/unit-1-study-guide.md`). It is in `not_tested` (never quizzed itself), but SKILL.md makes quiz/daily/cards/sheet/exam ask only at its depth: general terms, not unlisted examples (no specific transmitters); locations only for the 4 lobes; names only if on the guide. New unit guide = a new `unit-N-test-scope.md` page, same rule.
- Quiz tab: tick sources (→ wiki pages via each page's `> Raw:` line, `raw` in `/api/class` pages) or pages, or type a topic → `/api/study` quiz with `--pages` (topic limit 3000 chars).
- Calendar: top nav "Calendar" = `#/calendar`, month grid of every class's syllabus items from `/api/calendar` (color = the class's card color; click → that class's Deadlines tab).
- No repeats: `ingest.sh` tells Claude to grep the class wiki first and merge into a page that already covers the concept. `overlap.py <class>` (ingest lint step) prints page pairs that share many words (Jaccard >= 0.20 on 5+ letter words; real PSC 001 wiki: the correlation pages score 0.15, so they are different content). Home search box → `/api/search?in=wiki&q=` with no class = every class's wiki.
- Site UI: home = class cards; class page = tabs Wiki / Sources / Study / Deadlines / Progress (`#/c/<slug>/<tab>`). Study = make buttons + output cards from `/api/class` `outputs` (chips per type, quiz score from `studio/<class>/results.json`). A card opens in an iframe route `#/view/<path>` under a Back button + breadcrumb. ✕ on a card, source or wiki page → `/api/delete` → moves it to `.trash/` (gitignored), never erases
- `.claude/skills/karpathy-llm-wiki/` upstream, unmodified (ingest/query/lint rules)
- `.claude/skills/study-studio/` ours: `/study quiz|cards|slides|audio|video|map|report|table|exam <class>`
- `.models/` Kokoro TTS weights (gitignored)
- `serve.py` + `site/` local site: classes, uploads, YouTube links, auto-ingest (one at a time), viewer renders any `.md` with math. Vendored, MIT: marked 15.0.12 (sha256 3e7e7d7f…d0c), KaTeX 0.16.22 (`site/katex/`, woff2 fonts only, sha256 e8d88550…ae89). Reads only wiki/ raw/ studio/ site/. Writes need header `X-Class-Wiki: 1` and Host localhost (CSRF + DNS-rebinding guard)
- `docs/PLAN.md` design · `WORKS.md` prove-lines

## Conventions
- Model per job: ingest, lint, quiz, cards, slides, map, audio, video on **Sonnet** (`--effort low` in ingest.sh). Reports and exam prep need judgment: **Opus**.
- Every study output reads only `wiki/<class>/` and cites the page. Lecture raw files: `raw/<class>/YYYY-MM-DD-lecture-...md`.
- Lint: `python3 .claude/skills/karpathy-llm-wiki/scripts/check_evidence.py .` → 0 evidence errors.
- Tests: `cd .claude/skills/study-studio && python3 -m unittest discover tests` (stdlib only; audio test needs Docker running). Site + convert + overlap: `python3 -m unittest discover tests` from the project root.

## Gotchas
- YouTube 403 on video download = old yt-dlp. Fix: `brew upgrade yt-dlp` (2026.07.04 failed, 2026.08.19 worked). prepare_inbox falls back to captions only; failed files get a "Retry failed" button.
- The LaunchAgent needs `EnvironmentVariables` PATH (`~/.local/bin` for claude, `/opt/homebrew/bin` for pdftotext/yt-dlp/ffmpeg). Claude auth works from launchd (tested 2026-09-25).
- Lint "fidelity suspects" on YouTube sources are often false: caption lines repeat and split phrases across timestamps. Evidence errors are the real signal.
- `ingest.sh` holds `inbox/.ingest.lock` (dir + pid): a second run, by hand or from the site, waits its turn (wiki/index.md is shared). A lock left by a dead process is taken over automatically.
- Headless Chrome `--dump-dom` can hang forever and macOS has no `timeout`: wrap it in `perl -e 'alarm 30; exec @ARGV'`. A grep on the dump also matches the page's own script text, so count with care.
- A `@media (max-width:8.5in)` phone rule also fires on paper: a letter page IS 8.5in wide. The first notes sheet printed at 45% size. Write `@media screen and (...)` for anything that must not touch print.
- Headless Chrome screenshots have a 500 px minimum width. A `--window-size=390` shot is cropped, not a phone layout.
- Upstream tests need `examples/` too. Copy `SKILL.md LICENSE references scripts tests examples` together. Run them only in Docker: `docker run --rm --network none -v "$PWD/.claude/skills/karpathy-llm-wiki":/w:ro -w /w python:3.12-slim python -m unittest discover tests`.
- Kokoro runs only inside Docker (security rule: third-party code stays in the container). If Docker is down, make_audio.py falls back to macOS `say` (Samantha/Daniel) and says so.
- Kokoro speed ≈ 1 s of work per 1 s of audio (CPU). A 10-min overview takes ~10 min.
- exam_dates.py: key from `~/course-planner/.app-key`, sent only as `x-app-key` header. Never print or copy it. Render cold start 30-60 s (first call took 43 s). 401 = local key drifted from Render `APP_KEY`: tell Ethan.
- MAT 19A "Syllabus Quiz Sep 30" in course-planner is a GUESSED date, not an exam. exam_dates.py skips it (type quiz).
- Lecture transcripts live in the Lecture Notes site's browser localStorage. Its "Save .md" button downloads `lecture-<class>-<YYYY-MM-DD>.md` to ~/Downloads; ingest.sh picks those up.
- In the HTML templates, `[hidden]{display:none!important}` is required: `display:flex` rules beat the `hidden` attribute.
- Headless `claude -p` in ingest.sh cannot delete files (no `rm` in allowedTools). Keep generated JSON; do not ask for deletes.
- `claude -p` flags `--allowedTools` and `--add-dir` take many values and swallow a prompt placed after them ("Input must be provided..."). Always pass the prompt on stdin (`<<<`).
- build_quiz.py shuffles MCQ choices (models put the right answer first too often). Don't undo it in the prompt.
- ffmpeg `-shortest` with an image-concat input overshot by 3 s. make_video.py uses `-t <audio length>` instead.
- The dcg hook blocks `>` redirects into $HOME. Use the Write tool for files.
- Headless `/study daily` once asked "approve `./study.sh ... daily`?" instead of doing the work (it read "the site runs study.sh" and tried to recurse; not in allowedTools, so it stopped). All 4 classes got no quiz on 2026-09-27 and the loop does not retry that day. study.sh's prompt now says "you are already inside ./study.sh". No file after a run = read `inbox/<class>/.ingest.log`.
- Headless `claude -p` kills a Bash command after 2 min, or backgrounds it and quits before the file exists (first video run had no .mp4). study.sh sets `BASH_DEFAULT_TIMEOUT_MS`/`BASH_MAX_TIMEOUT_MS`=1 h and says "foreground only".
- Chat billing: never use `claude --bare` for the chat. `--bare` reads ONLY `ANTHROPIC_API_KEY` (pay per question). `--safe-mode` keeps the claude.ai plan login and still skips CLAUDE.md/hooks. serve.py also strips every `ANTHROPIC_*`/`CLAUDE*` var from the child env. Check: `claude auth status` → `"authMethod": "claude.ai"`.
- Tests live in `tests/` and each starts with a `sys.path.insert` to reach `serve.py` one folder up. Run from the project root: `python3 -m unittest discover tests`. A new test file needs the same first line.
